# V851 出厂身份配置

T5L/T5F 默认值为 CN、MCQX_QXY03、QXY03、HW-V1.0、
FW-V1.0.0。固件版本沿用本项目原值，表示出厂版本，不随运行中的版本显示更新。

## 保存和读取

- NOR 主块 0，**字地址 0x0100–0x017F**，共 128 字 / 256 字节；
  对应字节偏移 0x0200–0x02FF，两种地址单位均在 0x0800 之前。
- 避开 BOOT 控制字 0x0020–0x0021、设置索引 0x4000 / 0x10000
  和设置数据 0x4800 / 0x10800。这些都是 NOR 字地址。
- V851ProtocolInit() 在启动时加载一次。整条记录全 FF 或全 00 时，
  按宏默认值初始化一次，写后回读校验；有效记录只读，不与宏值比较、不迁移。
- 0x36 / 0x6A 工厂上报从已校验的内存缓存组包，不在运行时反复读写 Flash。
  恢复出厂、Wi-Fi 清除及接收版本上报均不改此记录。
- 非空白记录损坏、格式不支持或读写超时时，不覆盖原记录，也不上报未经确认的身份。
  其他协议任务继续运行；需在生产维护环节重新写入正确记录后重启。
- 这是应用层保留策略，不是 Flash 硬件写保护。生产烧录完成后，
  后续下载工具/BOOT 必须保留该区域；整片擦除会使它重新初始化。

## 记录格式

偏移为相对记录起点的**字节偏移**。字符串使用可打印 ASCII、以 00 结束，
剩余槽位补零，最长字符数比槽位长度少 1。

| 字节偏移 | 长度 | 内容 | NOR 字地址 |
| --- | ---: | --- | --- |
| 0x00 | 4 | 56 46 43 31（VFC1） | 0x0100 |
| 0x04 | 2 | 格式版本 00 01（大端） | 0x0102 |
| 0x06 | 2 | 记录长度 01 00（大端，256 字节） | 0x0103 |
| 0x08 | 8 | sales_country | 0x0104 |
| 0x10 | 64 | product_key | 0x0108 |
| 0x50 | 64 | model | 0x0128 |
| 0x90 | 32 | hardware_version | 0x0148 |
| 0xB0 | 32 | firmware_version | 0x0158 |
| 0xD0 | 46 | 保留，填 00 | 0x0168 |
| 0xFE | 2 | 前 254 字节的 CRC16/MODBUS，低字节在前 | 0x017F |

## 出厂时通过 Flash 修改

在仓库根目录生成完整记录，省略的参数从对应平台配置头读取：

    python tools/v851_factory_image.py --output outputs/factory/QXY03_factory.bin

其他生产批次可指定全部或部分字段，例如：

    python tools/v851_factory_image.py --output outputs/factory/custom_factory.bin --sales-country CN --product-key MCQX_QXY03 --model QXY03 --hardware-version HW-V1.0 --firmware-version FW-V1.0.0

文件是 **256 字节的配置记录，不是从 Flash 地址 0 开始的整片镜像，也不是 APP 固件**。
由工厂烧录工具写到主块 0 的字地址 0x0100（使用字节地址的工具填 0x0200）。
修改任何字段后应重新生成整条记录，避免 CRC 失效。

若使用现有 DGUS NOR 接口，停下正常业务后按以下顺序操作：

1. 将记录按原始字节顺序分段写入暂存 VP 0x2000–0x207F；
   该 VP 与应用 Flash 操作共用，生产工具需确保期间没有其他 NOR 操作。
2. 写 VP 0x0009，数据 01 00 20 00 00 80（NOR 地址、VP、字数）。
3. 写 VP 0x0008，数据 A5 00，触发主块 0 写入。
4. 等待 VP 0x0008 的命令高字节归零，再用同样参数和 5A 00 读回，
   比较完整 256 字节及 CRC；超时不得继续发送下一条 Flash 命令。
5. 重启，触发现有工厂上报按键 0x30A1，检查 0x36 / 0x6A 的五个字符串。

设备已存在有效记录时，仅修改头文件并下载 APP 不会改变出厂信息；
生产阶段要变更它，必须重写上述 Flash 记录并重启。
