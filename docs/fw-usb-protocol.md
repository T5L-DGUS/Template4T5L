# FW 参数通信与 U 盘更新

## 接口与地址

T5L 是 Modbus RTU 主机，控制板为地址 **1** 的从机。使用 **UART2，115200 baud，8N1**，沿用非 RS485 方向控制配置。R11 保持广告屏模式的 UART5、921600 baud。

当前 115200 设置：383385600 Hz 使用 /32、重装值 0x398；206438400 Hz 使用 /32、重装值 0x3C8。

UART2 同时接收 `5A A5 ... 82/83` DGUS 指令和地址 1 的 Modbus 响应，按完整帧分派，
支持拆包与连续帧。Modbus 数据中的 `5A A5` 不会被解释为 VP 写入。
82 写入是否回复 OK 仍由 `uartUART_82CMD_RETURN` 控制，当前关闭；83 正常回复读取数据。
DGUS CRC 开关沿用系统配置。单次 83 最多读取 124 字（带 CRC 时 123 字）。

所有 VP 均为一个 16 位字，范围在 `0x3600–0x3800` 内。

| VP | 含义 |
|---|---|
| `0x3600–0x3658` | FW 参数镜像，VP = `0x3600 + FW参数表中的十进制地址` |
| `0x3700` | 待写 FW 寄存器地址，填写表中的原始地址，不填 VP |
| `0x3701` | 待写原始 16 位数值 |
| `0x3702` | 写触发：界面填写地址、数值后置 1；程序消费后清零 |
| `0x3703` | 写结果：0 空闲，1 等待响应，2 成功，3 失败 |
| `0x3704` | 最近一次通信结果：0 未连接，1 正常，2 超时或异常 |
| `0x3705` | 最近错误：0 无错误，`0x0001–0x00FF` 控制板异常码，`0x0100` 超时，`0x0101` 写值/地址/触发不合法，`0x0102` 写忙 |
| `0x3780` | 视频材料可用：0 无，1 有 |
| `0x3781` | 软件材料可用：0 无，1 有 |
| `0x3782` | 视频更新完成：0 未完成，1 完成 |
| `0x3783` | 视频确认触发：界面置 1 |
| `0x3784` | 软件确认触发：界面置 1 |

其余地址保留。上电清零镜像、通信控制区和升级状态区；读取成功后更新镜像。温度等 Int 参数保留 16 位补码，不在通信代码中转换显示单位。例如 FW 地址 5 对应 VP `0x3605`，原始 `-150` 表示 `-15.0℃`。

## FW 读写流程

参数地址、读写权限和数值范围以 `FW参数表20260914.xlsx` 为准。取消每秒定时读取：上电首次进入当前页面时刷新一轮，之后仅在实际页面编号变化或设置写入成功后刷新。任务仍每 10 ms 调度，用于检查事件、处理写触发及超时；调度本身不产生周期报文。单请求响应超时仍为 500 ms，同一时间只有一个请求在途。

每轮按以下十进制区间依次读取，不读取备用、空白或缺失地址：

`0–1, 4–5, 8–9, 11, 13–14, 16–19, 21, 30–37, 39, 41–45, 50–51, 53, 69–77, 79–83, 85`。

读取期间的多次页面或设置事件最多合并为一轮后续刷新，不并发堆积请求。停留在同一页面且设置未改变时，完成当前刷新后保持静默。读取超时或收到异常响应时终止当前轮及已合并的后续刷新，记录错误，等待新的页面或设置事件；不自动定时重试。CRC、功能码、数据长度或 06 回显内容不匹配时不更新镜像，等待有效响应或超时。

界面修改参数时按顺序填写 `0x3700`、`0x3701`，最后将 `0x3702` 置 1。写提交优先于下一段读取；若正在等待读响应，触发保留到当前读请求结束后处理。若已有写操作在途，新写触发被拒绝并报告写忙。界面应在写结果为 1 时禁用提交按钮，避免覆盖尚未完成的操作。

只允许表中 R/W 且非备用的参数写入，并校验原始数值范围及枚举。FW 地址 11 的高压传感器类型允许 `0/1/2`；地址 `3、40、52、78` 为备用，不读取或写入。表中 R 参数只读。镜像和编辑暂存区分离，刷新不会覆盖用户尚未提交的数值。

普通设置提交值与已经成功读取或写入的有效镜像相同时，直接返回写成功，不发送 06，也不触发刷新；上电清零的镜像在通信成功前不视为有效值。实际发送 06 或通信失败时清除全部镜像的有效标记，保留显示值；成功回显或后续读取再恢复对应标记，避免用关联参数的旧值跳过提交。地址 14 为按键值，每次合法提交均可发送，即使与上次值相同。

06 成功回显后更新镜像及写结果，并触发一轮刷新以读取控制板的关联变化。写超时**不自动重发**，避免“按键值”等动作被重复执行；需要由用户确认后再次提交。镜像变化本身不会触发写入。

## FB 握手

所有 FB 帧固定 6 字节，无附加 CRC：`AA 55 00 02 FB xx`。

| xx | R11 → T5L | T5L → R11 |
|---|---|---|
| `00` | U 盘会话失效，清空升级状态和确认触发 | 忽略 |
| `01` | 有视频材料，置 `0x3780=1`，清除上次完成标志 | 用户确认视频更新 |
| `02` | 有软件材料，置 `0x3781=1` | 用户确认软件升级 |
| `03` | 视频全部搬运并同步成功，清 `0x3780`，置 `0x3782=1` | 忽略 |

T5L 接到 01/02 不自动回复。只有对应材料标志有效且界面将确认 VP 置 1 时才回发；触发消费后清零。00 清空所有升级标志与触发，03 不影响软件材料标志。界面资源未包含在本工程中，需按以上 VP 绑定按钮和显示控件。

## R11 执行与部署

新增 `usb_update_worker.c` 已加入 Makefile，并在 `public_filter_task` 启动。`rc.final` 不再独立启动自动升级脚本；必须同时部署更新后的程序、`/etc/usb_auto_update.sh` 和启动脚本。

脚本入口：

- `detect`：只读检查，退出值为材料位掩码：0 无、1 视频、2 软件、3 两者都有。
- `video`：重新检查材料后执行视频搬运，全部搬运及 sync 成功返回 0。
- `software`：重新检查版本后安装，版本最后提交，成功后执行 reboot。

内部管理模块还向脚本传入会话令牌及令牌文件路径。拔盘先使令牌失效，再向脚本进程组发送 TERM；脚本每个文件操作及清理步骤均检查存储/会话有效性。不会主动回滚已经成功替换的视频或软件文件，沿用原有逐文件替换语义；版本提交失败保留旧版本，禁止重启。

每秒检查挂载，插入后检测材料，等待期间每 30 秒重查。仅接受来自物理 R11 串口且与已发送材料通知相符的六字节确认；不从网络或业务队列授权升级。两项均确认时视频先执行，视频完成通知发出后才启动软件；只有软件被确认时可直接升级软件。执行过的项目本次插盘不再执行；失败日志提示重新插拔重试，无新增失败协议码。

队列中的旧材料/完成通知以会话标记过滤。拔盘后的确认无效；重新插入会重新检测和通知。固定 FB 协议没有会话字段，因此无法识别新一轮插入后才从线路到达的旧同值确认；一秒轮询也不能保证发现两次检查之间拔出又插回同一设备的动作。

## 验证

`tests/fw_protocol_test.c` 与 `tests/fw_test_platform.h` 模拟 VP、页面、时钟和 UART，验证真实 FW 状态机，覆盖首屏刷新、切页刷新、设置提交、同值抑制、按键重复发送、事件合并、错误后静默及参数表边界。运行方法见 `tests/README.md`。R11 管理模块和升级脚本属于外部工程，其测试不包含在本仓库中。

Keil 可直接构建 `project/T5L51.uvproj`。R11 完整程序仍需原 Tina SDK 和板端依赖；主机 ARM 编译检查仅覆盖新增管理模块，不等价于整机链接或硬件联调。
